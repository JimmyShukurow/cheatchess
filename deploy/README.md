# Deploying CheatChess (native, no containers)

```
git push main ──► GitHub Actions: build Vue + Go into ONE static binary
                └──► Ansible over SSH ──► VPS: write env file, back up DB, upload binary,
                                          switch symlink, systemctl restart, health check
```

On the VPS:
```
Internet ─► Caddy (apt, :443, automatic HTTPS) ─► cheatchess (systemd, 127.0.0.1:8080) ─► stockfish (apt)
                                                         └─ SQLite /var/lib/cheatchess/cheatchess.db
```
Vue doesn't run as a separate process. `npm run build` turns it into static files, and those are embedded in the Go binary.

| path on VPS | what |
|---|---|
| `/opt/cheatchess/releases/<id>/cheatchess` | uploaded binaries (last 5 kept) |
| `/opt/cheatchess/current` | symlink to the running release |
| `/etc/cheatchess/cheatchess.env` | config + secrets (root-only, **generated by Ansible**) |
| `/var/lib/cheatchess/` | database + `backups/` (owned by the `cheatchess` system user) |
| `/etc/systemd/system/cheatchess.service` | the service (hardened, auto-restart) |
| `/etc/caddy/Caddyfile` | reverse proxy config |

## Where env/secrets live

| file | in git? | purpose |
|---|---|---|
| `.env` (repo root) | ❌ gitignored | **local dev only** |
| `.env.example` | ✅ | documents every variable |
| `deploy/ansible/group_vars/all/vars.yml` | ✅ | non-secret prod settings (domain, paths) |
| `deploy/ansible/group_vars/all/vault.yml` | ✅ **encrypted** | prod secrets: admin emails, Google OAuth |
| `deploy/ansible/.vault_pass` | ❌ gitignored | password that decrypts the vault (also a GitHub secret) |
| `/etc/cheatchess/cheatchess.env` on VPS | – | generated from the two files above on each deploy |

To change a secret, run `ansible-vault edit group_vars/all/vault.yml`, then deploy. Don't edit the env file on the server by hand, because the next deploy overwrites it.

## One-time setup

### 1. Locally
```bash
sudo apt install ansible
cd deploy/ansible
ansible-galaxy collection install -r requirements.yml

cp inventory.example.ini inventory.ini          # your VPS IP / SSH user (root or a sudo user)
openssl rand -base64 32 > .vault_pass           # keep it safe (password manager)
cp vault.example.yml group_vars/all/vault.yml
nano group_vars/all/vault.yml                   # admin email, Google keys
ansible-vault encrypt group_vars/all/vault.yml
nano group_vars/all/vars.yml                    # set `domain`
```

### 2. Server (Ubuntu 22.04/24.04 or Debian 12+)
Point your domain's DNS A record at the VPS, then:
```bash
ssh-copy-id root@YOUR_VPS          # if you don't have key login yet
make provision                     # Caddy, Stockfish, systemd units, firewall, swap, backups
make deploy                        # build dist/cheatchess and ship it
```
For an ARM VPS, use `make deploy GOARCH=arm64`.

### 3. GitHub Actions (auto-deploy on push)
Repo → Settings → Secrets and variables → Actions:

| secret | value |
|---|---|
| `VPS_HOST` | VPS IP or hostname |
| `VPS_USER` | SSH user (`root`, or a user with passwordless sudo) |
| `SSH_PRIVATE_KEY` | a **dedicated deploy key** (`ssh-keygen -t ed25519 -f deploy_key`, add `deploy_key.pub` to the server's `~/.ssh/authorized_keys`) |
| `SSH_KNOWN_HOSTS` | output of `ssh-keyscan YOUR_VPS` |
| `ANSIBLE_VAULT_PASSWORD` | contents of `.vault_pass` |

Optional: add a **variable** `VPS_ARCH=arm64` for an ARM VPS.

After that, `git push origin main` runs the build and deploy in about 1–2 minutes. You can also start it from Actions → *Build & Deploy* → **Run workflow**.

## Day-to-day (on the VPS)
```bash
systemctl status cheatchess
journalctl -u cheatchess -f                         # live logs
sudo cheatchess-cli verify-email you@example.com    # run CLI commands with prod config
sudo cheatchess-cli backup /var/lib/cheatchess/backups/manual.db
systemctl list-timers cheatchess-backup             # daily backup at 03:30
```

Rollback, run from your PC:
```bash
cd deploy/ansible
ansible-playbook rollback.yml               # lists releases on the server
ansible-playbook rollback.yml -e to=<id>    # switch + restart
```

Restore a backup:
```bash
sudo systemctl stop cheatchess
sudo -u cheatchess cp /var/lib/cheatchess/backups/daily-2026-11-11.db /var/lib/cheatchess/cheatchess.db
sudo rm -f /var/lib/cheatchess/cheatchess.db-wal /var/lib/cheatchess/cheatchess.db-shm
sudo systemctl start cheatchess
```

Backups: one before every deploy and one daily (the last 14 are kept). Copy them off the server now and then, e.g. `rsync root@VPS:/var/lib/cheatchess/backups/ ./backups/`.

**Note:** live games are kept in memory, so a deploy or restart (about 1 s) ends any games in progress. Deploy when nobody is playing.

## Alternatives to Ansible
- **Plain SSH script in Actions:** `scp dist/cheatchess` to the server, then run `ssh 'ln -sfn … && systemctl restart cheatchess'`. It's simpler, but you set up the server and the env file by hand.
- **Run Ansible only from your PC** (`make deploy`) and skip GitHub Actions entirely.
